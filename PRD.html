1. 背景与目标

城市中养植物的人越来越多，但常见场景下找不到一个"够用就好"的工具：

  • 买了新植物，回家忘了它喜欢光还是阴，搜出来的资料五花八门，不知道信哪个。
  • 回老家看到一棵树，想知道它叫什么、有什么习性，搜索引擎不给力，植物识别 App 又要装新包。
  • 种了十几盆，想把"我的植物"集中起来随查随看，不想用笔记。
  • 手机里装过好几个植物 App，但都太重、要注册、要付费解锁，用两次就删了。

植语 是一款 移动端优先的轻量植物养护应用，针对上面三个场景做一个最小可用的产品：

  1. 随查随看 20 种常见室内植物 的养护参数，无需网络。
  2. 有定位时 按省推荐乡土植物，并支持 联网查询完整植物百科（定位中国时走中国植物志，否则走维基百科）。
  3. 把喜欢的植物 收藏到我的花园，离线可用。
产品定位：克制的有机极简风格，奶油纸感底 + 深墨绿文字 + 苔绿单一强调色，衬线标题。不做社区、不做打卡、不做付费解锁。用户打开就能查、就能收、就能关。

2. 范围

P0 · 最小完整旅程

  • 启动 App → 等待页显示 → 自动进入首页
  • 首页查看最近浏览 / 点「植物百科」进入本地植物百科 / 点定位胶囊触发定位
  • 本地植物百科查看离线 20 种 → 点搜索框进入联网查询 → 搜索 → 取消回到本地内容
  • 点任意植物打开详情面板 → 查看养护参数 / 收藏 → 关闭
  • 我的花园查看收藏列表 → 点进详情 → 移出收藏
  • 我的页：手动选择城市、查看数据来源、开关收藏提醒

P1 · 本期包含

  • GPS 定位与 IP 兜底（仅已授权时）
  • 省级常见植物排行（36 种乡土植物池 + 本地 20 种）
  • 联网数据源：定位中国时走 iplant.cn（中国植物志），未定位时走 zh.wikipedia.org
  • 收藏提醒开关 + 模态确认条
  • 本地植物百科与联网搜索合并为同一页面，点击搜索框即进入联网视图

明确排除

  • 植物图像识别（拍照识花）—— 需要重型模型 / 付费 API，不进本期
  • 养护任务提醒（浇水日历、通知推送）—— 依赖后台调度，复杂度不在 P0 范围
  • 社区 / 评论 / 用户上传 —— 不在产品定位
  • 账号系统与跨设备同步 —— 本地存储即可，多端同步是远期需求

3. 产品模型

用户

城市养植物的人。典型场景：居家养 3–20 盆；偶尔想查一株陌生植物；对养护信息的准确性敏感，不喜欢模糊的建议。

核心对象

对象用途关键标识生命周期
Plant一株植物的完整资料id（全局唯一）不持久化本身，持久化的是收藏 / 浏览中的引用
ProvincePlant省级常见植物排行的一行rank（当前省内）由定位 + 省份派生，无持久化
UserLocation用户当前定位结果province + city持久化到 localStorage

Plant 字段

字段类型含义来源
idstring全局唯一标识离线固定值 / 联网按名称派生（iplant-{value}、wiki-{title}、wild-{名称}、local-{index}）
namestring植物显示名（完整常用名）本地数据库 / 联网搜索建议解析
scientificNamestring拉丁学名Wikidata / 联网搜索建议 data 字段解析；无则留空
aliasesstring[]别名列表本地 / 联网解析
categorystring分类标签（观叶植物 / 多肉植物 / 乡土植物 / 中国植物志 …）数据源
light / water / humidity / temperature / soil / difficultystring养护六格参数hasCareInfo=true 时才有值
difficulty"新手友好" | "中等" | "有挑战"养护难度同上
toxicitystring毒性说明同上
descriptionstring一句话描述本地 / 联网解析
careTipsstring[]养护贴士列表hasCareInfo=true 时才有值
imageUrlstring图片地址Unsplash / 联网站点
source"local" | "online"数据来源创建时确定
hasCareInfoboolean是否有足够养护信息可展示本地 / 乡土植物=true，联网条目=false（除非数据充分）
externalUrlstring?条目原文页（中国植物志等）联网条目才有
关键约束：hasCareInfo=false 的 Plant 不得用默认值填充养护参数；详情面板显示「暂无养护资料」提示框。联网条目不预置养护参数，避免编造。

4. 共享规则

植物卡片网格

全界面统一 一排三个 紧凑网格（组件 LocalGridCard），间距 8px，卡片圆角 8px。所有植物列表（离线数组、省排行、联网结果、最近浏览、我的花园）共用此组件，保持视觉一致性。

搜索匹配规则

双向匹配：本地搜索必须同时满足——

  • 字段 haystack（name + scientificName + category + aliases）包含查询词，或
  • 查询词包含植物名 / 别名。

目的：搜「樟树」能命中名为「樟」的条目；搜「樟」也能命中「樟树」。

收藏状态

心形按钮有三种视觉：

状态外观点击行为
未收藏空心绿心弹「收藏 XX 到我的花园吗？」确认条 → 收藏
已收藏实心绿心弹「将 XX 移出我的花园吗？」确认条 → 移出

关闭详情面板时 不 弹任何确认条。提醒开关在「我的」页可关闭，关闭后心形直接执行。

退出搜索规则

退出联网查询（取消按钮 / 切到其他页签）时必须 同时重置查询词和搜索模式，确保再次进入本地植物百科时展示的是最开始的本地内容，而非上一次搜索残留结果。

图片加载失败

所有植物卡片和详情面板的封面图加载失败时，统一回退为 叶子图标（lucide-react Leaf，64px，苔绿色）。

持久化键

Key内容类型
plant-care-garden收藏的 Plant 对象数组完整对象（含 hasCareInfo）
plant-care-recent最近浏览的 Plant 对象数组完整对象，去重置顶，上限 40 条
plant-care-locationUserLocation 对象{ province, city, source, latitude?, longitude? }
plant-care-collect-prompt收藏提醒开关"0" = 关；未设置或 "1" = 开

FR-04 本地植物百科

P0P1

4.1 两种模式

同一页面承载两种内容，由搜索状态切换：

模式触发内容
本地（默认）页面初始进入 / 搜索取消 / 无搜索词未授权定位 → 固定离线 20 种；已授权 → 省排行（{省}常见植物 + 共 N 种）
联网查询点击或聚焦搜索框联网搜索结果，分两个分区展示

4.2 搜索框

页面顶部 sticky 吸顶。本地模式下显示省排行标题 + 副标题；联网模式下搜索框激活、出现"取消"按钮，取消则清空查询并切回本地模式。

4.3 省排行（已授权定位时）

标题："{省}常见植物" + 副标题 "共 N 种"。

  • 排行按编号 No.1 – No.18 展示，左上角角标。
  • 收藏优先排序：已收藏植物排在最前，其余保持原顺序。
  • 每行都有心形按钮、都可点开详情。
  • 36 种乡土植物池（provinceFlora.ts WILD_POOL）每种带完整养护资料；未命中乡土池的排行行，详情页提示"暂无养护资料"。

4.4 联网查询结果

搜索有结果时同屏展示两个分区：

分区标题内容
本地结果"本地结果"当前本地数据集（离线 20 种 / 省排行）内的双向匹配
联网结果定位中国 → "中国植物志"；未定位 → "植物百科"联网搜索返回的 Plant 对象列表

联网源按定位分流：定位中国（省名合法）→ iplant.cn；未定位 → zh.wikipedia.org。

4.5 竞态守卫

退出搜索（取消 / 切页签）会同时触发「联网空查询」和「本地空查询」两次。必须用 requestId 自增做竞态守卫，只采用最后一次发起的搜索结果，否则异步的联网空结果会覆盖本地 20 种导致取消后显示空态。

6. 数据来源与搜索链路

数据源矩阵

数据层来源用途联网？约束
本地 20 种硬编码离线兜底，所有定位状态下均可展示否每种 hasCareInfo=true
乡土养护池 36 种人工整理省排行中常见乡土植物的养护补充否每种带完整 WildCare
中国植物志 iplant.cn联网接口定位中国时的联网搜索源是无 CORS 头、缺 Referer 返回空，必须经代理补 Referer: https://www.iplant.cn/；CSP frame-ancestors 禁内嵌
维基百科 zh.wikipedia.org联网接口未定位时的联网搜索源是CORS origin=* 已放开；全文搜索 + 标题/重定向校验
CVH（中国植物物种名录）联网接口维基条目补充 distribution / 形态描述是必须经代理补 Referer；对室内栽培植物覆盖率低，失败静默

iplant.cn 搜索链路

代理层：iplant.cn 无 CORS 头，裸 fetch 会被浏览器拦截。开发环境通过 vite.config.ts 的 /api/iplant 代理，生产环境通过 server/index.mjs 的通用 proxy 路由，两者都补 Referer: https://www.iplant.cn/ 请求头。
  1. 解析中文名：用户输入关键词 → /ashx/searchautocomplete.ashx?query=关键词 → 返回 suggestions[{value, data}]。
    • data 有两种格式：中文名 学名 与 别名(正式名)。
    • 别名(正式名) 且别名与正式名互为简称/全称（如"樟树(樟)"）→ 显示名跟随用户搜索词，正式名收入 aliases。
    • 不互含（如"猴樟 的俗名也叫樟树"）→ 保留正式名防混淆。
    • 按正式名去重，id = iplant-{value}。
  2. 返回 Plant：最小 Plant 对象，hasCareInfo=false，source="online"，externalUrl 指向 iplant.cn 条目页。

维基百科搜索链路

  1. 全文搜索：action=query&list=search&srsearch=关键词 → 候选页。
  2. 第一轮过滤：排除消歧义页、影视/人物/地点等非植物条目（按分类判断）。
  3. 标题/重定向校验：用户查询词解析维基重定向目标（如"白掌"→"白鹤芋"），仅保留标题或重定向目标匹配查询词的条目。正文提及查询词但标题不匹配的条目（如"龙血树属"提及"龙血树"）必须排除。
  4. 摘要获取：批量请求页面摘要，对短条目（正文 < 30 字或无养护关键词）标记 hasCareInfo=false。
  5. 养护证据门槛：正文 ≥ 30 字 或 命中养护关键词（"喜"、"耐"、"宜"、"忌" 等）才视为有养护信息，否则标记 hasCareInfo=false。

CVH 补充链路（可选）

维基条目拿到后，按拉丁学名异步查询 CVH 名录补充 distribution（省级分布）和形态描述。失败静默返回 null，绝不影响维基搜索结果展示。代理同样需补 Referer。

术语含义
Plant一株植物的完整数据对象，含养护参数、描述、来源标记等

localPlants20 种固定离线植物数组，所有定位状态下都可展示
WILD_POOL36 种乡土植物养护池，每种带完整人工整理的 WildCare
iplant.cn / 中国植物志定位在中国时的联网搜索源，接口需代理补 Referer
双向匹配本地搜索的匹配规则：haystack 含查询词 或 查询词含植物名
